# Registro y Gestión de Defectos de Integración y Regresión (Post-Merge en Rama Develop) — SGRAI

Este documento formaliza el registro, seguimiento, remediación y certificación del ciclo de vida de los defectos detectados durante la **integración continua, auditoría forense post-merge y pruebas de regresión** en la rama principal `develop`, tras la aprobación e integración de los Pull Requests (PRs) de las historias de usuario del proyecto SGRAI (Dirección de Gestión de Riesgos de Desastres — Municipalidad de Valdivia).

El estándar aplicado se fundamenta en las directrices de aseguramiento de calidad de software **IEEE 829 / ISO/IEC/IEEE 29119**.

## 3. Casos de Prueba de Integración Vinculados (CP-INT)

Los defectos fueron detectados y verificados durante la ejecución de los siguientes procedimientos estándar en `develop`:

* **`CP-INT-00 (Setup BD)`:** Verificación de inicialización de base de datos desde cero y aplicación secuencial de migraciones Kysely (`npm run db:migrate`).
* **`CP-INT-01 (Build API / Frontend)`:** Compilación completa y generación de artefactos productivos (`npm run build`).
* **`CP-INT-02 (Contrato OpenAPI / Tipos)`:** Verificación de sincronización entre esquemas Zod, `GET /openapi.json`, tipos generados en `src/types/api-generated.d.ts` y chequeo estricto de TypeScript (`npx tsc --noEmit`).
* **`CP-INT-03 (Lint Frontend)`:** Verificación de análisis estático de código y reglas estrictas de ESLint en `sgrai-web` (`npm run lint`).
* **`CP-INT-04 (Tests Componentes / Hooks / Servicios)`:** Ejecución completa de la batería de pruebas unitarias y de integración con Vitest (`npm test`).
* **`CP-INT-05 (Auth Endpoints Protegidos / Proxy)`:** Validación de flujo de autenticación JWT, inyección de cabecera `Authorization: Bearer <token>`, proxy `/api/*` y guardias perimetrales de rol.
